# Resume Ingestion — Backend

> Part of: [Backend Specs Index](INDEX.md)

**Status:** Implemented  
**Trigger:** Employee uploads a PDF, DOCX, or DOC file via the Employee Dashboard.

---

## End-to-End Flow

```
Employee uploads file
        │
        ▼
POST /api/upload-resume
        │
        ├─ Validate file type + size
        ├─ Save original file to disk
        │
        ▼
agent_runner → root_agent → ingestion_agent
        │
        ├─ extract_resume(file_path, file_type)
        │       ├─ PDF  → Gemini 2.5 Flash (vision/text extraction)
        │       └─ DOCX → DocxTool.parse_docx() → Gemini structured parse
        │
        ├─ Normalize skills (ResumeNormalizer)
        ├─ Generate professional_summary if missing
        │
        ├─ generate_resume_docx(employee_data, output_path)
        │       └─ Fills org DOCX template
        │
        └─ Return { extracted_data, resume_path }
                │
                ▼
        db_service upserts:
          ├─ employee_data
          ├─ employee_resume_data
          └─ resume_store (version 1)
                │
                ▼
        Write audit event: RESUME_UPLOAD
                │
                ▼
        Return profile + resume path to frontend
```

## API Endpoint

### `POST /api/upload-resume`
**File:** `backend/routes/routes.py`  
**Status:** Implemented

**Request:** `multipart/form-data`
- `file`: binary (PDF | DOCX | DOC)
- `email`: string

**Validations (client + server):**
- Accepted MIME types: `application/pdf`, `application/vnd.openxmlformats-officedocument.wordprocessingml.document`, `application/msword`
- Max size: 10 MB (configurable via `MAX_UPLOAD_SIZE_MB` in settings)

**File storage:**
- Original: `uploads/{employee_id}/original/{filename}`
- Generated: `uploads/{employee_id}/generated/resume_v{N}.docx`

**Response:**
```json
{
  "success": true,
  "employee_id": "string",
  "profile": { "...employee_resume_data..." },
  "resume_path": "string",
  "version": 1
}
```

## Ingestion Agent

**File:** `backend/agents/ingestion_agent.py`  
**Framework:** Google ADK  
**Model:** Gemini 2.5 Flash  
**Instructions:** `backend/instructions/ingestion_agent_instruction.py`

### Step-by-step instruction flow
1. Receive `file_path` and `file_type` from root_agent.
2. Call `extract_resume(file_path, file_type)` → structured JSON.
3. Normalize extracted skills using `ResumeNormalizer`.
4. If `professional_summary` is empty or missing, generate one from skills + work experience.
5. Call `generate_resume_docx(employee_data, output_path)` → DOCX file path.
6. Return final JSON: `{ extracted_data: {...}, resume_path: "..." }`.

### Tools registered on ingestion_agent
| Tool | File | Purpose |
|---|---|---|
| `extract_resume` | `tools/resume_tool.py` | Parse PDF or DOCX into structured JSON |
| `generate_resume_docx` | `tools/resume_tool.py` | Generate org-standard DOCX from extracted data |

## Extraction Tool

**File:** `backend/tools/resume_tool.py` — `extract_resume(file_path, file_type)`

### PDF path
- Uses `PyMuPDF` (fitz) to extract raw text from PDF pages.
- Sends text + `extraction_instruction` system prompt to Gemini 2.5 Flash.
- Gemini returns structured JSON matching the extraction schema.

### DOCX path
- Delegates to `DocxTool.parse_docx(file_path)`.
- `DocxTool` reads paragraphs and table content from the DOCX.
- Passes raw text + `extraction_instruction` to Gemini for structured parsing.

## Extraction Schema

**File:** `backend/instructions/extraction_instruction.py`

The Gemini model is instructed to return JSON with exactly this structure:

```json
{
  "personal_info": {
    "name": "",
    "email": "",
    "mobile": "",
    "designation": "",
    "department": "",
    "current_role": "",
    "location": "",
    "total_experience": 0,
    "relevant_experience": 0,
    "joining_date": ""
  },
  "professional_summary": "",
  "skills": [
    { "category": "", "name": "", "proficiency": "", "years_of_experience": 0 }
  ],
  "work_experience": [
    {
      "project_name": "",
      "client_name": "",
      "role": "",
      "domain": "",
      "start_date": "",
      "end_date": "",
      "duration": "",
      "team_size": 0,
      "technology_stack": [],
      "responsibilities": []
    }
  ],
  "education": [
    { "degree": "", "university": "", "graduation_year": 0 }
  ],
  "certifications": [
    { "name": "", "provider": "", "completion_date": "" }
  ],
  "achievements": [],
  "interests": [],
  "search_tags": []
}
```

`search_tags` is auto-generated by Gemini as a flat list of normalized skill/tech keywords for fast regex search in MongoDB.

## Skill Normalizer

**File:** `backend/tools/normalizer.py` — `ResumeNormalizer`

Run after extraction, before DB write.

**Rules applied:**
- Canonical naming: `javascript` → `JavaScript`, `k8s` → `Kubernetes`, `js` → `JavaScript`
- Deduplication: merges exact and alias duplicates
- Category assignment from built-in taxonomy

**Taxonomy categories:**
```
Programming Languages · Frameworks · Cloud · Database ·
DevOps · Testing · AI/ML · Mobile · Other
```

## Database Writes After Ingestion

| Collection | Operation | Fields Written |
|---|---|---|
| `employee_data` | upsert by `email` | All personal_info fields + bench_status |
| `employee_resume_data` | upsert by `email` | Full extracted + normalized resume data |
| `resume_store` | upsert by `email` | `current_resume_path`, `current_version`, `versions[]` append |
| `audit_data` | insert | `event_type: RESUME_UPLOAD`, timestamp, employee_id |
